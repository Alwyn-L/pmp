# 供应链九大系统：数据流、主数据归属与上线优先级

> 本文是对《一图讲透9大供应链系统》一文的补充，聚焦原文着墨不足的三个落地问题：
> ① 系统间数据流与集成接口清单；② 主数据由谁统管；③ 按业务形态的上线优先级。
>
> **适用对象**：处于选型或实施阶段的企业管理者、信息化负责人。

---

## 一、系统间数据流与集成接口清单

### 1.1 核心数据流主线

```text
PLM（产品/BOM/工艺）
  → ERP（主数据、计划、财务）
    → SRM（采购执行）→ MES（生产执行）→ WMS（仓储作业）
      → OMS（订单履约）→ TMS（配送）
        → CRM（客户反馈/售后）
SCM：横跨需求计划与供应计划，做供需平衡
```

### 1.2 接口清单（按数据流向）

| 序号 | 源系统 | 目标系统 | 传递数据 | 触发方式 | 频率建议 | 关键字段/说明 |
|---|---|---|---|---|---|---|
| 1 | PLM | ERP | 物料主数据、BOM、工艺路线、工程变更（ECN） | 变更审批生效后推送 | 实时/准实时 | 物料编码、版本号、生效日期；ECN 需带变更单号 |
| 2 | PLM | MES | BOM、工艺路线、图纸版本 | 工单下达前同步 | 按工单 | 确保车间用对图纸版本 |
| 3 | ERP | SRM | 采购申请、采购订单、供应商主数据、价格 | 单据审批后推送 | 实时 | 采购订单号、行项目、交期 |
| 4 | SRM | ERP | 采购订单确认、发货通知（ASN）、收货回执、对账单、发票 | 供应商协同动作触发 | 实时/日批 | 四单合一（订单/收货/发票/付款） |
| 5 | ERP | MES | 生产订单、工单、物料需求 | 计划下达 | 按班次/实时 | 工单号、工序、计划数量 |
| 6 | MES | ERP | 生产报工、完工入库、物料消耗、废品 | 报工/完工时回传 | 实时/准实时 | 实际工时、良品/不良品数量 |
| 7 | ERP | WMS | 出入库指令、库存调拨单、盘点任务 | 单据生成后 | 实时 | 单据号、物料、批次、库位 |
| 8 | WMS | ERP | 实际出入库记录、库存台账、批次/序列号 | 作业完成后回传 | 实时/准实时 | 库存数量以 WMS 实绩为准回写 |
| 9 | OMS | WMS | 发货单、出库指令、分仓分配结果 | 订单审核/分单后 | 实时 | 订单号、SKU、数量、仓库 |
| 10 | WMS | OMS | 出库完成、库存扣减、打包发货状态 | 出库作业完成 | 实时 | 运单号、包裹信息 |
| 11 | OMS | TMS | 运输任务、收货地址、时效要求 | 发货单生成后 | 实时 | 订单号、体积重量、时效 |
| 12 | TMS | OMS | 在途轨迹、签收状态、异常回单 | 承运商回传 | 实时/定时 | 运单号、节点时间、签收人 |
| 13 | CRM | ERP/OMS | 客户主数据、销售订单、信用额度 | 成交/下单时 | 实时 | 客户编码、信用校验结果 |
| 14 | ERP/OMS | CRM | 订单状态、发货与售后信息 | 状态变更 | 实时/日批 | 供销售跟进与客户服务 |
| 15 | SCM | ERP/SRM/MES | 需求预测、主生产计划、补货计划、产能约束 | 计划周期（周/月） | 周期性 | S&OP 输出，驱动采购与生产 |
| 16 | ERP | SCM | 实际销售、库存、在途、供应商交期 | 日/周批 | 周期性 | 计划输入的实际数据 |

### 1.3 集成方式建议

| 类型 | 适用场景 | 实现方式 | 关键要求 |
|---|---|---|---|
| 实时类 | 订单、库存、报工、出入库 | API 接口 / 消息队列（MQ） | 保证幂等与重试 |
| 批量类 | 对账、计划、报表 | 定时批处理（日批/周批） | 需有对账与差错处理机制 |
| 主数据类 | 物料、BOM、供应商、客户 | 由主数据系统（或 ERP）统一分发 | 单向发布、订阅消费，禁止多源写入 |

**接口治理**：统一接口编码规范、留痕日志、失败告警；建议维护一份《接口清单台账》，标注责任系统与责任人。

## 二、主数据由谁统管

**核心原则：一物一码、一源一主、单向分发、订阅消费。**

每个主数据只有一个"权威源系统"（System of Record），其他系统只订阅、不反写。

| 主数据类型 | 权威源系统（建议） | 分发对象 | 说明与注意事项 |
|---|---|---|---|
| 物料主数据 | ERP（或独立 MDM） | PLM、SRM、WMS、MES、OMS | PLM 在研发阶段可创建临时物料，量产前须在 ERP 正式建档并回写编码；避免 PLM 与 ERP 双源 |
| BOM | PLM（设计 BOM）→ ERP（制造 BOM） | MES、SRM、SCM | 设计 BOM 由 PLM 管，制造 BOM 由 ERP/工艺部门管；ECN 变更须走审批并同步下游 |
| 供应商主数据 | SRM（准入与资质）→ ERP（财务/结算主体） | WMS、TMS、SCM | SRM 管准入、资质、绩效；ERP 管结算账户与应付；两者以供应商编码对齐 |
| 客户主数据 | CRM（或 ERP 销售模块） | OMS、ERP、TMS | 客户编码、信用额度、收货地址；电商多渠道客户需做去重合并规则 |
| 组织/人员/权限 | ERP 或统一身份平台 | 全部系统 | 组织架构、角色、审批流；建议对接统一身份认证（SSO） |
| 仓库/库位 | WMS | ERP、OMS、TMS | 库位编码由 WMS 维护，ERP 只同步仓库层级 |
| 承运商/运价 | TMS | ERP、OMS | 运价规则、承运商资质 |

**治理机制建议：**

1. **设岗**：设立主数据管理岗（可由信息化部门兼任），负责编码规则、准入审批、变更审核。
2. **流程**：建立主数据变更流程：申请 → 审核 → 发布 → 订阅系统确认接收。
3. **核对**：定期（月度）做主数据一致性核对，重点核对物料、供应商、客户编码在 ERP/SRM/CRM/WMS 中的一致性。
4. **编码先行**：物料、供应商、客户、仓库、BOM 版本号的编码规则尽早统一——一旦定下，后期迁移成本极高。

## 三、按企业业务形态的上线优先级

### 3.1 离散制造（多品种、小批量、BOM 复杂）

**典型特征**：产品结构复杂、研发迭代频繁、按订单/预测混合生产、车间工序多。

| 优先级 | 系统 | 理由 |
|---|---|---|
| P0 | ERP | 底座，承载财务、采购、库存、生产计划与主数据 |
| P0 | PLM | BOM 与工程变更是离散制造的源头，晚建会导致 ERP 数据返工 |
| P1 | MES | 车间透明化、报工与质量追溯，解决"生产进度看不见" |
| P1 | SRM | 供应商多、外协多，采购协同与交期跟踪价值高 |
| P2 | WMS | 物料种类多、批次管理需求强时优先 |
| P2 | SCM | 计划复杂度上升后引入，做 S&OP 与供需平衡 |
| P3 | OMS/TMS/CRM | 按销售渠道与物流复杂度决定 |

**上线顺序**：ERP + PLM 并行 → MES → SRM → WMS → SCM → OMS/TMS。

### 3.2 流程制造（连续生产、配方为主、批次追溯强）

**典型特征**：配方（Recipe）管理、批次/效期追溯、产能连续、联副产品。

| 优先级 | 系统 | 理由 |
|---|---|---|
| P0 | ERP | 财务、采购、库存、成本核算底座 |
| P0 | MES | 流程行业对批次追溯、配方执行、设备监控要求高，MES 价值突出 |
| P1 | WMS | 批次/效期管理是刚需，库存准确率直接影响合规 |
| P1 | SRM | 原料供应商集中、质量协同与到货跟踪关键 |
| P2 | SCM | 产能与需求平衡、原料补货计划 |
| P2 | TMS | 危化品/冷链等运输合规要求高时优先 |
| P3 | PLM/CRM/OMS | PLM 侧重配方管理；OMS 按渠道复杂度决定 |

**上线顺序**：ERP → MES + WMS → SRM → SCM → TMS → OMS/CRM。

### 3.3 零售电商（多渠道、订单量大、履约时效敏感）

**典型特征**：多渠道订单、SKU 多、库存分散、履约时效要求高、退换货频繁。

| 优先级 | 系统 | 理由 |
|---|---|---|
| P0 | OMS | 多渠道订单汇总、分单、库存锁定是核心痛点 |
| P0 | WMS | 多仓库存准确率与拣货效率直接决定履约 |
| P1 | ERP | 财务、采购、库存核算底座（可与 OMS/WMS 并行建设） |
| P1 | CRM | 客户资产、会员与售后，电商获客成本高 |
| P2 | TMS | 物流成本与时效跟踪，快递对接为主 |
| P2 | SRM | 自营商品采购协同；平台型可弱化 |
| P3 | SCM/PLM/MES | 有自有生产或复杂计划时再引入 |

**上线顺序**：OMS + WMS 先行（解决履约）→ ERP → CRM → TMS → SRM/SCM。

### 3.4 通用原则

1. **ERP 是底座但不必最先全上**：零售电商可先上 OMS/WMS 解决履约，再补 ERP 财务。
2. **主数据先行**：无论哪种形态，物料/客户/供应商编码规则须在上线前统一。
3. **接口预留**：每上一个系统，同步维护接口清单，避免后期"补接口"成本翻倍。
4. **小步快跑**：按"最小可用模块"上线，先跑通一条业务主线（如订单 → 仓储 → 配送），再扩展。

## 四、成本与投入提示（简要）

| 投入项 | 说明 |
|---|---|
| 软件许可/订阅 | 按用户数、模块、部署方式（SaaS/私有化）差异大 |
| 实施服务 | 通常为软件费用的 1~2 倍，含调研、配置、培训、上线 |
| 接口开发 | 每个接口按复杂度计，系统越多接口成本越高，建议一次性规划接口清单 |
| 主数据治理 | 常被低估，编码清洗与历史数据迁移可能占项目周期 20%~30% |
| 运维与迭代 | 年费约为软件费用的 15%~20% |
