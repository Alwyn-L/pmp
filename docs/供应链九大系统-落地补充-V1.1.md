# 供应链九大系统：数据流、主数据归属与上线优先级

> 本文是对《一图讲透9大供应链系统》一文的补充，聚焦原文着墨不足的三个落地问题：
> ① 系统间数据流与集成接口清单；② 主数据由谁统管；③ 按业务形态的上线优先级。
>
> **适用对象**：处于选型或实施阶段的企业管理者、信息化负责人。
>
> **V1.1 修订**：数据流图改为以 ERP 为中心的星型拓扑；接口清单补充主数据分发、逆向物流、TMS→ERP 运费结算共 8 条；主数据权威源细化到字段级并明确编码生成方。

## 一、系统间数据流与集成接口清单

### 1.1 核心数据流拓扑（以 ERP 为中心的星型）

```text
                              ┌──────────────┐
                              │     PLM      │
                              └──────┬───────┘
                                     │ 物料（临时码）、BOM、工艺路线、ECN
                                     ▼
                     ┌───────────────────────────────────┐
                     │           ERP（集成枢纽）           │
                     │  主数据 · 计划 · 财务 · 供需存运归集  │
                     └──┬──────┬──────┬──────┬──────┬────┘
                        │      │      │      │      │
                     采购协同 生产执行 仓储作业 订单履约 客户/售后
                        │      │      │      │      │
                    ┌───▼──┐┌──▼───┐┌──▼───┐┌──▼───┐┌──▼───┐
                    │ SRM  ││ MES  ││ WMS  ││ OMS  ││ CRM  │
                    └──────┘└──────┘└──────┘└──────┘└──────┘

  ※ 图中每条连线均对应 1.2 接口清单中的一行；箭头方向与字段以接口表为准，
     本图只表达"谁与 ERP 有接口"，不表示数据只能单向串行流动。
  ※ PLM 另向 MES 直发 BOM、工艺路线与图纸版本（工单下达前同步）。
  ※ SCM ↔ ERP：下发需求预测/主生产/补货/产能约束，上传实际销售/库存/在途/供应商交期。
  ※ TMS 另向 ERP 回传运费对账与计费明细，作为物流成本进成本与应付的唯一入口。
  ※ 两条不经 ERP 中转的直连链：
     履约：OMS → WMS（发货单/出库指令）→ OMS（出库完成）；OMS → TMS（运输任务）→ OMS（轨迹/签收）
     逆向：OMS → WMS（退货入库指令）→ ERP（退货入库实绩）
```

### 1.2 接口清单（按数据流向）

| 序号 | 源系统 | 目标系统 | 传递数据 | 触发方式 | 频率建议 | 关键字段/说明 |
|---|---|---|---|---|---|---|
| 1 | PLM | ERP | 物料（临时码）、BOM、工艺路线、工程变更（ECN） | 变更审批生效后推送 | 实时/准实时 | 物料临时码、版本号、生效日期；ECN 需带变更单号；正式编码由 ERP 建档后回写（见序号 2） |
| 2 | ERP | PLM | 正式物料编码、物料状态、版本回写 | ERP 建档/变更审核通过 | 实时 | 解决双源：PLM 只持临时码，正式编码以 ERP 为准，PLM 不得自行发布正式编码 |
| 3 | ERP | SRM | 物料、供应商、采购价格主数据 | 主数据发布 | 实时 + 每日全量核对 | 供应商编码由 SRM 生成、ERP 订阅，禁止两边分别建档 |
| 4 | ERP | MES | 物料、BOM、工艺路线主数据 | 主数据发布 | 实时 + 按工单校验 | BOM 以 ERP 制造 BOM（MBOM）为准，不接收 PLM 的 EBOM 直接投产 |
| 5 | ERP | WMS | 物料、仓库层级、包装规格 | 主数据发布 | 实时 + 每日全量核对 | 仓库编码由 ERP 生成；库位编码由 WMS 生成并回传映射 |
| 6 | ERP | OMS | 物料、仓库、价格、可售库存策略 | 主数据发布 | 实时 | 客户主数据由 CRM 提供（见序号 21），本行不重复下发客户 |
| 7 | PLM | MES | BOM、工艺路线、图纸版本 | 工单下达前同步 | 按工单 | 确保车间用对图纸版本 |
| 8 | ERP | SRM | 采购申请、采购订单、供应商、价格 | 单据审批后推送 | 实时 | 采购订单号、行项目、交期 |
| 9 | SRM | ERP | 采购订单确认、发货通知（ASN）、收货回执、对账单、发票 | 供应商协同动作触发 | 实时/日批 | 订单/收货/发票三单匹配，付款按匹配结果执行 |
| 10 | ERP | MES | 生产订单、工单、物料需求 | 计划下达 | 按班次/实时 | 工单号、工序、计划数量 |
| 11 | MES | ERP | 生产报工、完工入库、物料消耗、废品 | 报工/完工时回传 | 实时/准实时 | 实际工时、良品/不良品数量 |
| 12 | ERP | WMS | 出入库指令、库存调拨单、盘点任务 | 单据生成后 | 实时 | 单据号、物料、批次、库位 |
| 13 | WMS | ERP | 实际出入库记录、库存台账、批次/序列号 | 作业完成后回传 | 实时/准实时 | 库存数量以 WMS 实绩为准回写 |
| 14 | OMS | WMS | 发货单、出库指令、分仓分配结果 | 订单审核/分单后 | 实时 | 订单号、SKU、数量、仓库 |
| 15 | WMS | OMS | 出库完成、库存扣减、打包发货状态 | 出库作业完成 | 实时 | 运单号、包裹信息 |
| 16 | OMS | WMS | 退货入库指令（RMA）、退货单、质检要求 | 退货审核通过 | 实时 | RMA 单号、原订单号、退货原因、是否可再销售 |
| 17 | WMS | ERP | 退货入库实绩、不良品隔离/报废记录 | 退货收货完成 | 实时/准实时 | 库存回补与应收冲减依据；不良品进隔离库，不进入可用库存 |
| 18 | OMS | TMS | 运输任务、收货地址、时效要求 | 发货单生成后 | 实时 | 订单号、体积重量、时效 |
| 19 | TMS | OMS | 在途轨迹、签收状态、异常回单 | 承运商回传 | 实时/定时 | 运单号、节点时间、签收人 |
| 20 | TMS | ERP | 运费对账、计费明细、承运商结算单 | 月度/批次对账 | 日批/月批 | 运单号、计费重、运费构成；物流成本进成本与应付的唯一入口 |
| 21 | CRM | ERP/OMS | 客户主数据、销售订单 | 成交/下单时 | 实时 | 客户编码、收货地址；信用额度以 ERP 授信为准，CRM/OMS 只消费校验结果 |
| 22 | ERP/OMS | CRM | 订单状态、发货与售后信息 | 状态变更 | 实时/日批 | 供销售跟进与客户服务 |
| 23 | SCM | ERP/SRM/MES | 需求预测、主生产计划、补货计划、产能约束 | 计划周期（周/月） | 周期性 | S&OP 输出，驱动采购与生产 |
| 24 | ERP | SCM | 实际销售、库存、在途、供应商交期 | 日/周批 | 周期性 | 计划输入的实际数据 |

### 1.3 集成方式建议

| 类型 | 适用场景 | 实现方式 | 关键要求 |
|---|---|---|---|
| 实时类 | 订单、库存、报工、出入库 | API 接口 / 消息队列（MQ） | 保证幂等与重试 |
| 批量类 | 对账、计划、报表 | 定时批处理（日批/周批） | 需有对账与差错处理机制 |
| 主数据类 | 物料、BOM、供应商、客户、仓库 | 由第二章的权威源系统统一分发（默认 ERP；引入独立 MDM 则 MDM 接管） | 单向发布、订阅消费，禁止多源写入；以"实时增量 + 每日全量核对"防止增量丢失 |

**接口治理**：统一接口编码规范、留痕日志、失败告警；建议维护一份《接口清单台账》，标注责任系统与责任人。

## 二、主数据由谁统管

**核心原则：一物一码、一源一主、单向分发、订阅消费。**

每个主数据只有一个"权威源系统"（System of Record），其他系统只订阅、不反写。

| 主数据类型 | 权威源系统（建议） | 分发对象 | 说明与注意事项 |
|---|---|---|---|
| 物料主数据 | ERP | PLM、SRM、WMS、MES、OMS | **编码由 ERP 统一生成**。PLM 研发阶段只建临时码，量产前由 ERP 正式建档并通过接口 2 回写正式编码，PLM 不得自行发布正式编码。若后续引入独立 MDM，则 MDM 接管编码与分发，ERP 转为订阅方 |
| BOM | PLM（设计 BOM / EBOM）→ ERP（制造 BOM / MBOM，唯一分发源） | MES、SRM、SCM | 设计 BOM 由 PLM 管；**MBOM（含损耗率、替代料、工时）由 ERP/工艺部门维护**，EBOM→MBOM 的转换与差异由 ERP 负责。MBOM 不回写 PLM，避免制造数据污染设计端；ECN 变更须走审批并同步下游 |
| 供应商主数据 | SRM（编码生成 + 准入/资质/绩效）→ ERP（补结算账户） | WMS、TMS、SCM | **编码由 SRM 生成**，ERP 订阅建档，禁止 ERP 侧新建供应商编码；结算账户、付款条件、税率由 ERP 维护且不回写 SRM |
| 客户主数据 | B2B/直销：ERP 销售模块；B2C/多渠道：CRM（或 CDP） | OMS、ERP、TMS | 按渠道形态二选一，不得两边建档；B2C 多渠道客户须做去重合并。**信用额度不属于客户主数据**，由 ERP 授信后分发 CRM/OMS 做下单校验 |
| 组织/人员/权限 | 有统一身份平台：以平台为源；无平台：以 ERP 为源 | 全部系统 | 二选一，不允许 ERP 与平台同时维护。SSO 只解决认证，组织/岗位仍需按主数据同步 |
| 仓库/库位 | 仓库：ERP；库位：WMS | ERP、OMS、TMS | **仓库编码由 ERP 生成后下发 WMS**；库位编码由 WMS 生成并回传 ERP 做层级映射，ERP 不直接维护库位 |
| 承运商/运价 | 结算主体：ERP（供应商编码）；运价与履约：TMS | ERP、OMS | 承运商须先在 ERP 建供应商档案，TMS 承运商编码与供应商编码做映射，避免同一承运商出现两套应付 |

**治理机制建议：**

1. **设岗**：设立主数据管理岗（可由信息化部门兼任），负责编码规则、准入审批、变更审核。
2. **流程**：建立主数据变更流程：申请 → 审核 → 发布 → 订阅系统确认接收。
3. **核对**：定期（月度）做主数据一致性核对，重点核对物料、供应商、客户编码在 ERP/SRM/CRM/WMS 中的一致性。
4. **编码先行**：物料、供应商、客户、仓库、BOM 版本号的编码规则尽早统一——一旦定下，后期迁移成本极高。

## 三、按企业业务形态的上线优先级

### 3.1 离散制造（多品种、小批量、BOM 复杂）

**典型特征**：产品结构复杂、研发迭代频繁、按订单/预测混合生产、车间工序多。

| 优先级 | 系统 | 理由 |
|---|---|---|
| P0 | ERP | 底座，承载财务、采购、库存、生产计划与主数据 |
| P0 | PLM | BOM 与工程变更是离散制造的源头，晚建会导致 ERP 数据返工 |
| P1 | MES | 车间透明化、报工与质量追溯，解决"生产进度看不见" |
| P1 | SRM | 供应商多、外协多，采购协同与交期跟踪价值高 |
| P2 | WMS | 物料种类多、批次管理需求强时优先 |
| P2 | SCM | 计划复杂度上升后引入，做 S&OP 与供需平衡 |
| P3 | OMS/TMS/CRM | 按销售渠道与物流复杂度决定 |

**上线顺序**：ERP + PLM 并行 → MES → SRM → WMS → SCM → OMS/TMS。

### 3.2 流程制造（连续生产、配方为主、批次追溯强）

**典型特征**：配方（Recipe）管理、批次/效期追溯、产能连续、联副产品。

| 优先级 | 系统 | 理由 |
|---|---|---|
| P0 | ERP | 财务、采购、库存、成本核算底座 |
| P0 | MES | 流程行业对批次追溯、配方执行、设备监控要求高，MES 价值突出 |
| P1 | WMS | 批次/效期管理是刚需，库存准确率直接影响合规 |
| P1 | SRM | 原料供应商集中、质量协同与到货跟踪关键 |
| P2 | SCM | 产能与需求平衡、原料补货计划 |
| P2 | TMS | 危化品/冷链等运输合规要求高时优先 |
| P3 | PLM/CRM/OMS | PLM 侧重配方管理；OMS 按渠道复杂度决定 |

**上线顺序**：ERP → MES + WMS → SRM → SCM → TMS → OMS/CRM。

### 3.3 零售电商（多渠道、订单量大、履约时效敏感）

**典型特征**：多渠道订单、SKU 多、库存分散、履约时效要求高、退换货频繁。

| 优先级 | 系统 | 理由 |
|---|---|---|
| P0 | OMS | 多渠道订单汇总、分单、库存锁定是核心痛点 |
| P0 | WMS | 多仓库存准确率与拣货效率直接决定履约 |
| P1 | ERP | 财务、采购、库存核算底座（可与 OMS/WMS 并行建设） |
| P1 | CRM | 客户资产、会员与售后，电商获客成本高 |
| P2 | TMS | 物流成本与时效跟踪，快递对接为主 |
| P2 | SRM | 自营商品采购协同；平台型可弱化 |
| P3 | SCM/PLM/MES | 有自有生产或复杂计划时再引入 |

**上线顺序**：OMS + WMS 先行（解决履约）→ ERP → CRM → TMS → SRM/SCM。

### 3.4 通用原则

1. **ERP 是底座但不必最先全上**：零售电商可先上 OMS/WMS 解决履约，再补 ERP 财务。
2. **主数据先行**：无论哪种形态，物料/客户/供应商编码规则须在上线前统一。
3. **接口预留**：每上一个系统，同步维护接口清单，避免后期"补接口"成本翻倍。
4. **小步快跑**：按"最小可用模块"上线，先跑通一条业务主线（如订单 → 仓储 → 配送），再扩展。

## 四、成本与投入提示（简要）

| 投入项 | 说明 |
|---|---|
| 软件许可/订阅 | 按用户数、模块、部署方式（SaaS/私有化）差异大 |
| 实施服务 | 通常为软件费用的 1~2 倍，含调研、配置、培训、上线 |
| 接口开发 | 每个接口按复杂度计，系统越多接口成本越高，建议一次性规划接口清单 |
| 主数据治理 | 常被低估，编码清洗与历史数据迁移可能占项目周期 20%~30% |
| 运维与迭代 | 年费约为软件费用的 15%~20% |
